# SafeGuard-PQ Release 3: evidence summary

*Software v0.3.0 · results recorded 2026-11-22 · Word version: [`SafeGuard-PQ_Release3_Evidence_Summary.docx`](SafeGuard-PQ_Release3_Evidence_Summary.docx)*

Release 3 answers open validation questions about the scoring model, the optimizer, plan evaluation and the traffic
rules with new experiments rather than new claims. Every number below comes from the JSON artifacts in
[`benchmarks/results/`](../../benchmarks/results/) and is regenerated by one command.

> **Claim boundary:** all results are configuration-level, obtained on synthetic configurations and instances, a simulated hospital ward and public CICIoMT2024 test captures; none is a certification of security, safety or standards conformance.

## E8: optimizer against an integer-programming optimum

Fifty synthetic portfolios per size (constraint tightness τ ∈ {0.25, 0.5, 0.75}); the reference optimum is from the
HiGHS 1.16.0 MIP solver, which matches exhaustive search on 100/100 small instances. Gap = 100 · (f\* − f) / f\*.

<!-- docx-widths: 10,22,22,22,24 -->
| n | Mean gap, shipped planner | Max gap, shipped planner | Mean gap, greedy start only | Runtime, shipped vs ILP |
|---:|---:|---:|---:|---:|
| 20 | 0.301 % | 3.04 % | 1.19 % | 17 vs 16 ms |
| 50 | 0.195 % | 1.05 % | 0.43 % | 67 vs 24 ms |
| 100 | 0.089 % | 0.36 % | 0.29 % | 190 vs 41 ms |
| 200 | 0.055 % | 0.28 % | 0.16 % | 811 vs 54 ms |

Gaps shrink as n grows, while exactly optimal plans fall from 76 % to 28 %. Local search, not annealing, closes the
gap (annealing beat the greedy start in 7 of 200 instances). The MIP solver is exact and, from n = 50, faster
(Figure 1). E3 (500 instances, n ≤ 14): 97.6 % optimal, mean gap 0.053 %.

## E7: sensitivity of the scoring model

Ten built-in scenarios, seed 2026; ρ = Spearman rank correlation of the PQ risk scores with the default run.

<!-- docx-widths: 9,37,16,14,11,13 -->
| Design | Perturbation | Verdict changes | Status changes | Max \|ΔS\| | ρ |
|---|---|---|---|---:|---:|
| S1 | each category weight ×0.8 or ×1.2, renormalised (12 configurations) | ≤ 1/10 | 0/10 | 4 | 1.000 |
| S2 | severity points ×0.8 / ×1.2 | 4/10 / 2/10 | 0/10 | 17 | 1.000 |
| S3 | principle-score deductions ×0.8 / ×1.2 | 0/10 | 0/10 | 0 | 1.000 |
| S4 | lifetime threshold L = 5 / 15 / 20 years (default 10) | 0, 0, 2 of 10 | 1, 0, 0 of 10 | 20 | ≥ 0.997 |
| S5 | planner principle weights ×0.8 / ×1.2 (plans identical in 10/10) | 0/10 | 0/10 | 0 | 1.000 |

Verdict changes are crossings of the 25 / 50 / 75 thresholds, not re-rankings. At L = 5 years the 8-year EHR scenario
turns UNSAFE (S 26 → 46).

## E9: plan evaluation by reassessment

The plan's mitigations are applied to the configuration by code (`optimizer/reassess.py`) and the pipeline is re-run.
Shipped planner:

<!-- docx-widths: 30,22,14,15,19 -->
| System | Baseline S (status) | Projected S | Reassessed S | Status after plan |
|---|---|---:|---:|---|
| icu_gateway_critical | 61 (UNSAFE) | 26 | 0 | SAFE |
| nextgen_pq_safe | 0 (SAFE) | 0 | 0 | SAFE |
| ehr_tls13_classical | 26 (AT_RISK) | 26 | 0 | SAFE |
| clinical_ai_phi | 0 (UNSAFE) | 0 | 0 | SAFE |
| secret_exposure | 10 (UNSAFE) | 0 | 0 | SAFE |
| legacy_worst_case | 89 (UNSAFE) | 46 | 43 | UNSAFE |
| tight_budget_qiro | 61 (UNSAFE) | 58 | 46 | UNSAFE |
| pq_downgrade_prompt | 0 (UNSAFE) | 0 | 0 | SAFE |
| hybrid_transition | 23 (AT_RISK) | 0 | 0 | SAFE |
| infusion_syn_flood | 46 (UNSAFE) | 26 | 0 | UNSAFE |

Projected and reassessed scores agree for 5/10 systems (mean error 9.3 points, max 26). The projection is pessimistic
where findings share a mitigation and optimistic where a mitigation cannot be checked at configuration level
(`rate_limiting` leaves the SYN-flood finding: `infusion_syn_flood` stays UNSAFE at S = 0). The opt-in
shared-root-cause planner cuts the error to 2.7. Reassessing every feasible action subset (413 pipeline runs) shows the
shipped plan attaining the best outcome in 8/10 systems, at the lowest cost in 1/10 (shared-root-cause planner: 9/10,
7/10); in the worked example a 58 000 USD subset matches the 98 000 USD plan (Figure 2).

## E10: traffic rules on held-out windows

Thresholds are tuned on development windows only; held-out 100-row windows are evaluated once. P1 develops on the
synthetic simulator split (120 windows) and tests on the CICIoMT2024 test split (3 446); P2 develops on the first half
of every test capture (1 721) and tests on the second half (1 725). The packet-size baseline flags windows whose mean
packet size leaves the benign 1st–99th percentile band. Brackets: 95 % bootstrap intervals.

<!-- docx-widths: 9,24,11,10,23,23 -->
| Protocol | Predictor | Precision | Recall | F1 | FPR |
|---|---|---:|---:|---:|---:|
| P1 | rules (tuning kept every shipped threshold) | 0.997 | 0.973 | 0.985 [0.982, 0.987] | 0.027 [0.011, 0.044] |
| P1 | packet-size baseline | 0.906 | 1.000 | 0.951 | 0.848 |
| P2 | rules (4 of 5 rules re-tuned) | 1.000 | 0.973 | 0.987 [0.982, 0.991] | 0.000 [0.000, 0.000] |
| P2 | packet-size baseline | 1.000 | 0.978 | 0.989 | 0.000 |

The rules keep F1 near 0.98 on unseen windows, but 89 % of the windows are attacks, mostly small-packet floods: the
packet-size baseline comes close in P1 and is slightly better in P2, and always answering "attack" scores 0.942. The
rules add a low false-positive rate (P1) and the attack type, not a higher F1. Small classes stay uncertain (P2: ARP
spoofing 5/9 detected, Wilson 95 % interval 27–81 %; Figure 3). On the threshold-selection split (E6) the benign
false-positive rate is an optimistic 2.7 %.

## E11: attack simulation

282 runs on the simulated hospital ward (14 attacks, 9 devices, 3 seeds). In 249 the attack's precondition was
present, and 234 of these raised a new finding from the agent the catalogue names for the attack. All 15 misses are
passive harvest-now-decrypt-later captures on devices already flagged for long-lifetime exposure. After the catalogue
mitigation the simulator refused all 249 re-injections, a property of its mitigation model, not of real attackers. In
the ICU Q-Day drill the fleet mean S rises from 31.0 to 35.2 and UNSAFE devices from 5 to 7; the fleet-wide
mitigations bring both to 0 (Figure 4).

## E12: standards mapping

[`standards_mapping.md`](standards_mapping.md) and `GET /api/v1/standards-map` trace each of the 42 finding types to the
IEEE/UL 2933-2024 principles it affects (trust, identity, privacy, protection, safety, security), its score deduction,
its PQ-score category and weight, and public references (NIST FIPS 203/204 and IR 8547, RFC 8996, HIPAA, OWASP, MITRE
CWE/ATT&CK). The standard's clause numbers are not public, so the mapping stops at principle level and is not a
conformance claim.

## Limitations

- Configurations and instances are synthetic; no observed clinical system was assessed and no other tool compared.
- Scoring constants are design choices: E7 bounds their effect but does not calibrate them.
- Without the CICIoMT2024 train split, held-out results rest on the test split under two weaker protocols.
- Reassessment and attack simulation check configuration consistency only; network mitigations are not modelled.
- No device measurements; deployment costs come from published figures.

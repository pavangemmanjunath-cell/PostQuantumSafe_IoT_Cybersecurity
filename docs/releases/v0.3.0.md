# PostQuantumSafe IoT Cybersecurity v0.3.0 — Release 3: validation evidence

**TIPPSS SafeGuard-PQ: a TIPPSS-based (IEEE/UL 2933-2024) agentic testing framework that checks whether IoT and
edge-device environments are safe against post-quantum attacks, implemented first for healthcare.**

## Overview

Release 3 answers open validation questions about the scoring model, the optimizer, plan evaluation and the traffic
rules with software, experiments and documents rather than with text alone. It adds a reassessment stage that applies
a remediation plan to the configuration by code and re-runs the pipeline, an optional shared-root-cause planner, an
adjustable lifetime threshold, a standards traceability map served by the API, five new reproducible experiments with
machine-readable artifacts, a synthetic held-out traffic dataset, a one-command reproduction pipeline that CI runs for
pushes and pull requests, a Research Results tab with one section per experiment, print-ready figures, and a short evidence summary
(Markdown and Word) in `docs/release-3/`.

The default assessment behaviour is unchanged: for the same input and seed the findings, scores, verdicts and plans
are identical to v0.1.0/v0.2.0 (verified by the parity tests and by a byte-level comparison of the planner output on
80 instances).

> This is a research prototype. Rules are transparent heuristics, costs are illustrative and all bundled data is
> synthetic. It is not a certified security assessment, does not certify conformance with IEEE/UL 2933-2024 and must
> not be used for clinical decision-making.

## Highlights

- **Reassessment of remediation plans.** `optimizer/reassess.py` applies the plan's catalogue mitigations to the
  request (TLS fields, device logs, prompt filtering and redaction), re-runs detection and scoring, and reports summed
  benefit, projected score and reassessed score side by side. Network mitigations cannot be verified at
  configuration level and are reported as *unmodelled*. API: `POST /api/v1/assessments/{id}/reassess`.
- **Shared-root-cause planner (opt-in).** `options.group_shared_root_causes=true` merges findings fixed by the same
  mitigation into one decision unit costed once and records the catalogue dependency hybrid ML-KEM → TLS 1.3. On
  the ten scenarios it reduces the mean gap between projected and reassessed score from 9.3 to 2.7 points.
- **Adjustable lifetime threshold.** `assumptions.lifetime_threshold_years` (default 10) replaces the hard-coded
  ten-year rule; Mosca's test and the override are reported separately.
- **Standards traceability.** `GET /api/v1/standards-map`: 42 finding types → TIPPSS pillars → deduction → score
  category and weight → public references (pillar level; IEEE/UL 2933-2024 clause numbers are not public).
- **Research Results tab** with sections for E3, E8, E7, E9, E6, E10, E11 and E12, all read from committed artifacts.
- **One-command reproduction.** `python benchmarks/run_all.py --check` re-runs every experiment, redraws the figures,
  rebuilds the Word summary and compares every regenerated artifact with the committed one; the CI job `reproduce`
  runs it for pushes to `main` and `feat/**` branches and for pull requests (without the CICIoMT2024 files, which are
  not redistributed).
- **Evidence summary** (`docs/release-3/`): a five-minute summary of every Release 3 result in Markdown and Word
  (`SafeGuard-PQ_Release3_Evidence_Summary.docx`), with the threat model, formulas transcribed from the code,
  deployment-feasibility analysis from published figures and the standards mapping as appendices; seven result
  figures (one message each, SVG, PDF, 300-dpi PNG).

## New experiments (all artifacts in `benchmarks/results/`, 2026-11-22, Python 3.13.5)

| Id | Experiment | Headline result |
|---|---|---|
| E7 | Scoring sensitivity (`sensitivity_analysis.py`) | SAFE/AT_RISK/UNSAFE status never changes under ±20 % perturbations of weights, points or deductions (Spearman ρ = 1.0); verdict flips in ≤ 4/10 scenarios; L = 5 y changes one status, L = 20 y two verdicts |
| E8 | Scalability vs ILP (`qiro_scalability.py`) | mean gap to the HiGHS optimum 0.30 % (n = 20) to 0.055 % (n = 200), max ≤ 3.0 %; annealing adds nothing beyond greedy for n ≥ 50; ILP cross-check 100/100; MIP exact and up to 15× faster |
| E9 | Plan reassessment (`plan_reassessment.py`) | shipped plan reaches SAFE in 7/10 systems; projected vs reassessed differ by 9.3 points on average (max 26); worked example best by reassessment but not cheapest (58 k vs 98 k USD) |
| E10 | Held-out traffic rules (`traffic_rules_holdout.py`) | cross-source and temporal protocols on the CICIoMT2024 test split: F1 0.985 / 0.987 with FPR 2.7 % / 0 %; a packet-size baseline matches this F1 on the flood-dominated split; small classes uncertain |
| E11 | Attack simulation (`attack_simulation_eval.py`) | 282 runs on the hospital ward: 234/249 exploitable runs detected, 249/249 re-injections blocked by the simulator model; passive capture invisible where the exposure is already flagged |
| E12 | Standards traceability (`standards_map.py`) | 42 rows, every pillar covered, public references only |

E3 (97.6 % optimal, mean gap 0.053 %) and E6 (same-split traffic rates) were re-run with v0.3.0: results unchanged.

## Changes since v0.2.0

### Added
- `optimizer/reassess.py`, `POST /assessments/{id}/reassess`, request retention in the assessment store.
- `optimize(..., group_shared_root_causes=...)`, `RunOptions.group_shared_root_causes`, `planner_mode` and
  `root_cause_groups` in every planner result.
- `Assumptions.lifetime_threshold_years`; parameterised `pq_score(weights, points)` and `tippss_pillars(deduct)`.
- `knowledge/standards_map.py` and `GET /api/v1/standards-map`.
- Benchmarks `sensitivity_analysis.py`, `qiro_scalability.py` (+ `_ilp.py`, `_stats.py`), `plan_reassessment.py`,
  `traffic_rules_holdout.py`, `attack_simulation_eval.py`, `make_synthetic_traffic_dataset.py`, `make_figures.py`;
  seven result artifacts.
- `datasets/synthetic_holdout/` (1.3 MB, synthetic, Apache-2.0).
- Research Results sections (`frontend/src/pages/results/`), 12 browser tests (was 10 in v0.1.0).
- `benchmarks/run_all.py` (one-command pipeline with `--check`) and the CI job `reproduce`; CI also runs on pushes to
  `feat/**` branches.
- `docs/release-3/` evidence summary, `scripts/gen_standards_map_doc.py`, `scripts/build_release3_docx.py` (+ `.cjs`,
  docx-js installed on demand outside the repository), `scripts/svg_to_pdf.cjs`; optional `benchmark` extra
  (`highspy`, `matplotlib`).
- 74 backend tests (222 in total, was 148).

### Changed
- README, `docs/novelty.md`, `docs/limitations.md`, `docs/reproducibility.md`, `benchmarks/README.md`,
  `datasets/README.md` rewritten around the Release 3 evidence; the ICU drill text describes defences as simulated
  configuration changes.
- Every artifact regenerated and compared with `run_all.py --check`: deterministic values identical to the committed
  record, which is kept (dates, version strings and runtimes are machine-dependent).
- `traffic_rules_holdout.py` records portable folder labels instead of local paths (`--data-label`,
  `--train-data-label`).
- Result figures redrawn for print (one message, at most two panels, 8 pt text, no second y-axis); the long evidence
  document was replaced by a short summary and its Word file renamed to `SafeGuard-PQ_Release3_Evidence_Summary.docx`.
- Version 0.3.0 in `backend/pyproject.toml`, `safeguard_pq.__version__`, `frontend/package.json`, `CITATION.cff`.

### Not changed
- Detection rules and thresholds, scoring constants, default planner output, simulator, PDF reports, CLI.

## Upgrade

No migration is needed. New request fields are optional with backwards-compatible defaults.

```bash
git fetch --tags && git checkout v0.3.0
pip install -e "backend[dev]"            # add "[benchmark]" for the ILP reference and figures
cd frontend && npm ci && npm run build
```

## Known limitations

Unchanged in kind from v0.1.0 and now quantified: scoring constants are design choices (E7 bounds their effect);
scenarios are hand-written synthetic systems; the CICIoMT2024 train split was not available, so the capture-level
held-out protocol awaits it; reassessment and attack simulation are configuration-level checks; the standards mapping
is at pillar level; no device measurements were made; no comparison with other tools exists. See
[`docs/limitations.md`](https://github.com/pavangemmanjunath-cell/PostQuantumSafe_IoT_Cybersecurity/blob/main/docs/limitations.md)
and [`docs/release-3/README.md`](https://github.com/pavangemmanjunath-cell/PostQuantumSafe_IoT_Cybersecurity/blob/main/docs/release-3/README.md).

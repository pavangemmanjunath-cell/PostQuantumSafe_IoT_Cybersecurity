# PostQuantumSafe IoT Cybersecurity v0.3.0 — research results and transparency release

**TIPPSS SafeGuard-PQ: a TIPPSS-based (IEEE 2933-2024) agentic testing framework that checks whether IoT and
edge-device environments are safe against post-quantum attacks, implemented first for healthcare.**

Release type: minor release · research prototype / early-stage concept · Apache-2.0
Release date: 2026-11-22 · Tag: `v0.3.0` · Previous release: `v0.2.0` (2026-10-24)

Location of these notes in the repository: [`docs/releases/v0.3.0.md`](https://github.com/pavangemmanjunath-cell/PostQuantumSafe_IoT_Cybersecurity/blob/main/docs/releases/v0.3.0.md)

## Overview

This release makes the project's evidence easier to inspect and states its limits more precisely. A new
**Research Results** tab in the web application shows the committed benchmark outputs next to their caveats. The README
and research documents now say what the software contributes and what it does not claim. The seeded optimizer
benchmark was re-run, and the simulation text no longer implies real-world protection.

The assessment agents, scoring rules, optimizer and REST API are unchanged from v0.1.0/v0.2.0, so assessment results
for the same input and seed are the same as in those releases.

> This is a research prototype. Rules are transparent heuristics, costs are illustrative and all bundled data is
> synthetic. It is not a certified security assessment, does not certify conformance with IEEE 2933-2024 and must not
> be used for clinical decision-making.

## Highlights

- **Research Results tab (`/#results`).** Reads `benchmarks/results/qiro_optimality.json` and
  `benchmarks/results/traffic_rules_eval.json` at build time. It shows the optimizer and traffic-rule metrics with the
  run date, Python version, seed and limitations, so the numbers on screen are always the committed artifacts.
- **Re-run QIRO benchmark.** 500 synthetic instances, instance-generator seed 0, Python 3.13.5, run on 2026-11-22.
- **Clearer novelty and scope.** A new "Novelty and scope" section in the README and an updated `docs/novelty.md`
  describe the contribution as an integrated, explainable engineering workflow. It is not a new post-quantum primitive,
  a new quantum algorithm or a standards-compliance claim.
- **Honest simulation wording.** The ICU Q-Day drill now says that defences are *simulated configuration changes*. A
  reassessment checks whether the edited configuration satisfies the framework's own rules. It is not evidence that a
  mitigation works against a real attacker.

## Measured results

| Benchmark | Result | Notes |
|---|---|---|
| QIRO (annealing + local search) vs. exhaustive optimum, 500 synthetic instances | 97.6% optimal; mean gap 0.0532%; p95 gap 0.0000%; max gap 6.0606% | Re-run 2026-11-22, seed 0; identical objective metrics to v0.1.0 |
| QIRO (annealing only), same instances | 94.8% optimal; mean gap 0.1913%; p95 gap 0.1616%; max gap 20.1592% | Same run |
| Mean optimizer runtime per instance, including the exact solver | 8.62 ms | Depends on the machine and its load; not a performance guarantee |
| Traffic rules on the CICIoMT2024 test split (window level, 100 rows) | 2.7% benign false positives; 76.5–100% detection per attack file | **Not re-run.** Recorded 2026-10-17. Optimistic: thresholds were selected after inspecting the same split |

The traffic dataset is external and not redistributed, so the traffic benchmark could not be re-run for this release.
The optimizer results measure closeness to the exact optimum of the same synthetic objective. They do not establish
clinical or security effectiveness.

## Known limitations

These are unchanged from v0.1.0. The rules are heuristics. Remediation costs are illustrative. The scoring weights are
design choices and are not calibrated against incident data. The framework evaluates supplied configurations and does
not scan live devices. The server is in-memory, unauthenticated and for local use only. The following are **not**
part of this release:

- held-out (train/test) evaluation of the traffic rules, with precision, recall, F1 and confidence intervals;
- an integer-programming baseline or optimizer instances larger than n = 14 actions;
- sensitivity analysis of scoring weights, severity deductions or the ten-year confidentiality threshold;
- plan evaluation that accounts for shared root causes or action dependencies;
- comparisons against other tools.

See [`docs/limitations.md`](https://github.com/pavangemmanjunath-cell/PostQuantumSafe_IoT_Cybersecurity/blob/main/docs/limitations.md)
and [`ROADMAP.md`](https://github.com/pavangemmanjunath-cell/PostQuantumSafe_IoT_Cybersecurity/blob/main/ROADMAP.md).

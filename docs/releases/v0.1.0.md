# PostQuantumSafe IoT Cybersecurity v0.1.0 — first public release

**TIPPSS SafeGuard-PQ: a TIPPSS-based agentic testing framework (IEEE 2933-2024: Trust, Identity, Privacy, Protection,
Safety, Security) that checks whether an IoT and edge-device environment is safe against post-quantum (quantum computer)
attacks. Implemented first for healthcare (clinical IoT).**

## Overview

Many IoT and edge devices still use classical public-key cryptography (RSA, ECDHE, ECDSA) that a future quantum
computer could break. Traffic recorded today can be decrypted later ("harvest now, decrypt later"), and device
certificates could be forged. This release provides an open framework in which **14 cooperating agents test an
environment, decide whether it is `SAFE`, `AT_RISK` or `UNSAFE`, explain every conclusion with evidence, and plan the
countermeasures** within a budget and a maintenance window. Healthcare (an ICU ward) is the first worked use case;
the device profiles and attack catalogue are built to be extended to other IoT and edge domains.

> This release shares a thought process and a working prototype to invite discussion, reproduction and improvement.
> Rules are transparent heuristics, costs are illustrative and all bundled data is synthetic. It is not a certified
> security assessment and must not be used for clinical decision-making.

## Built on the TIPPSS framework

TIPPSS (Trust, Identity, Privacy, Protection, Safety, Security) is the security and privacy framework for connected
devices standardised for healthcare in IEEE 2933-2024 (*Clinical IoT Data and Device Interoperability with TIPPSS*).
Every finding in this framework is tagged with the TIPPSS pillars it affects, each pillar is scored from 0 to 100, the
remediation planner gives extra weight to Safety and Privacy, and every report shows the six pillar scores. The release
adds the post-quantum view to TIPPSS: a quantum computer weakens Protection, Identity and Trust at once, so post-quantum
risk is judged together with the other pillars. Healthcare (ICU gateways, infusion pumps, patient monitors and clinical
AI assistants) is where the framework is implemented and tested end to end. See the "Built on the TIPPSS framework"
section of the README for the pillar-to-agent map. This is an independent research prototype, not affiliated with or
endorsed by IEEE, and it does not certify conformance with the standard.

## Highlights

- **TIPPSS-based assessment:** six pillar scores (IEEE 2933-2024) for every system and fleet, with the weakest pillar named.
- **Agentic testing pipeline:** 14 deterministic agents (crypto inventory, post-quantum identification, device identity,
  prompt injection, privacy, secrets, clinical safety, traffic anomaly, TIPPSS mapping, risk scoring, QIRO planner,
  explainability, report writer) with a live view of every agent step.
- **Post-quantum identification:** every primitive is classified against NIST FIPS 203/204/205 and the NIST IR 8547
  draft timeline, including hybrid ML-KEM groups, and harvest-now-decrypt-later exposure is evaluated with Mosca's
  inequality.
- **Post-quantum attack simulations:** harvest-now-decrypt-later capture, legacy-fallback downgrade, classical-only
  group fallback, quantum certificate forgery (CRQC) and PQ-downgrade prompt injection, plus network and AI attacks,
  each linked to the agent that detects it and the defence that stops it.
- **Q-Day what-if:** change the assumed years to a quantum computer and see which devices become exposed.
- **One-click use case:** the "ICU Q-Day drill" runs record-now → weaken → Q-Day → AI misuse → detect → respond → verify.
- **Explainable by construction:** evidence per finding, exact score attribution, counterfactuals, core-issue
  (root-cause) analysis and full agent traces.
- **Constraint-aware planning (QIRO):** reaches the exact optimum on 97.6% of 500 synthetic planning instances.
- **"Is the environment safe?" PDF reports** for one system or a whole fleet.

## What is included

| Component | Technology |
|---|---|
| Backend and agents | Python 3.11+, FastAPI, Pydantic (`backend/`) |
| Web interface | React, TypeScript, three.js / React Three Fiber, Lucide icons (`frontend/`) |
| CLI | `safeguard-pq serve | scenarios | assess` |
| Optional LLM narrative | any OpenAI-compatible endpoint (incl. local Ollama) or Anthropic, configured in `.env`; receives redacted data only and never changes a verdict |
| Tests | 148 backend tests (unit, integration, parity with the v0 prototype) and 10 Playwright browser tests |
| Benchmarks | QIRO optimality and traffic-rule evaluation scripts with recorded results |

## Measured results (from this release)

| Benchmark | Result |
|---|---|
| QIRO vs exhaustive optimum, 500 synthetic instances | 97.6% optimal; mean gap 0.05%; worst case 6.06% |
| Full multi-agent assessment of one system | about 6 ms on a laptop CPU |
| Traffic rules on the CICIoMT2024 test split (window level) | 2.7% benign false positives; 76.5–100% detection per attack file (optimistic: thresholds tuned on the same split) |

## Get started

```bash
git clone https://github.com/pavangemmanjunath-cell/PostQuantumSafe_IoT_Cybersecurity.git
cd PostQuantumSafe_IoT_Cybersecurity
powershell -ExecutionPolicy Bypass -File scripts\dev.ps1     # Windows
./scripts/dev.sh                                               # Linux / macOS
```

Without the GUI: `pip install -e "backend[dev]"` then `safeguard-pq assess --scenario icu_gateway_critical --pdf report.pdf`.

## Contribute — everyone is welcome

This is a community project. Useful first contributions:

- device profiles for new IoT / edge domains (smart buildings, energy and battery storage, industrial edge, vehicles);
- new post-quantum or conventional attack simulations and the matching detection rules;
- ingestion of real scanner output (TLS scans, CycloneDX cryptographic bills of materials);
- dataset adapters for openly licensed IoT datasets and held-out evaluations of the traffic rules;
- independent reproductions on Linux and macOS, documentation and translations.

Read [CONTRIBUTING.md](https://github.com/pavangemmanjunath-cell/PostQuantumSafe_IoT_Cybersecurity/blob/main/CONTRIBUTING.md),
open an issue using the bug, feature or research-question form, and send a pull request.
Please report security problems privately as described in SECURITY.md.

## Known limitations

Rule-based heuristics; illustrative remediation costs; scoring weights not calibrated against incident data; the
framework evaluates supplied configurations and does not scan live devices; in-memory, unauthenticated server for
local use; traffic-rule results are optimistic. See `docs/limitations.md`.
